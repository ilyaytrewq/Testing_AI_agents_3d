# Кофейный бариста

Тематический чат с LLM: помощник по домашнему завариванию кофе. Тема задаётся системным промптом в [config/app.yaml](config/app.yaml). Вход по общему ключу доступа, история одна на всех и хранится в PostgreSQL — не пишите в чат личные данные. Модель видит только системный промпт и текущий вопрос.

## Быстрый запуск

Нужны Docker Compose v2 и OpenAI-совместимый API модели.

```sh
git clone https://github.com/ilyaytrewq/Testing_AI_agents_3d.git && cd Testing_AI_agents_3d
make env
docker compose -f compose.local.yaml up --build -d --wait
```

`make env` создаёт `.env` со случайными секретами. Перед запуском впишите в него `APP_LLM__BASE_URL`, `APP_LLM__MODEL` и `LLM_API_KEY`. Откройте **http://127.0.0.1:8000** и введите `APP_ACCESS_KEY` из `.env`. Остановка с сохранением истории: `docker compose -f compose.local.yaml down` (без `-v`). Другая модель, запуск без Docker, настройки — в [docs/details.md](docs/details.md).

## Авторизация

Ключ общий, задаётся на сервере в `APP_ACCESS_KEY`.

- **Передача.** Один раз, в заголовке `X-Access-Key` запроса `POST /api/session`. Не в URL, не в теле, не в `localStorage`; после входа поле очищается.
- **Проверка.** Формат, затем сравнение HMAC-SHA256-дайджестов за постоянное время (`hmac.compare_digest`).
- **Сессия.** В таблице `sessions` создаётся запись (срок 8 часов), браузер получает cookie `chat_session`: подписанная, `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, внутри только id сессии. Каждый запрос проверяет запись в БД.
- **Хранение.** В браузере ключа нет, только `HttpOnly`-cookie. На сервере ключ, секрет подписи, ключ модели и пароль БД живут в переменных окружения, в `.env` (права `0600`, в `.gitignore`) или в файлах (`NAME_FILE`); в Kubernetes — в Secret.
- **Отзыв.** «Выйти» вызывает `DELETE /api/session` и отзывает запись на сервере. Смена `APP_ACCESS_KEY` отзывает все сессии: в записи хранится отпечаток ключа (HMAC с секретом `APP_SESSION_SECRET`).
- **CSRF.** `POST` и `DELETE` должны нести `Origin`, равный `auth.public_origin`, плюс `SameSite=Lax`.
- **Перебор.** Вход: 10 попыток за 60 секунд на адрес, затем `429`. Сообщения: 10 за 60 секунд на гостя, чтобы не сжечь квоту модели. Счётчики в памяти процесса.

Подробности (прокси, гость «Вы», секреты из файлов): [docs/details.md](docs/details.md#авторизация-подробности).

## Защита темы

Включена по умолчанию (секция `guard` в [config/app.yaml](config/app.yaml)); обе проверки делает LLM-классификатор.

- **Вопрос.** Отдельный вызов LLM возвращает `ON_TOPIC` или `OFF_TOPIC` и язык вопроса. Не по теме (в том числе о модели, промпте и ключах): фиксированный отказ на языке вопроса, основная модель не вызывается.
- **Промпт.** Вопрос уходит основной модели в `<user_question>` как данные; системный промпт запрещает код и разговоры о модели, провайдере и собственных инструкциях.
- **Ответ.** Тот же классификатор проверяет ответ; нарушение заменяется отказом.
- **Сбой не равен отказу.** Ответ классификатора без вердикта даёт отказ. Если классификатор не ответил, вернул ошибку или трижды подряд не дал вердикта, пользователь получает `502`/`504`, а вопрос сохраняется как неотвеченный. Ответа в обход проверки нет.
- **Цена.** До двух дополнительных вызовов LLM на сообщение.

Формат вердикта, модели с рассуждениями, отдельный классификатор: [docs/details.md](docs/details.md#защита-темы-подробности).

## Устройство проекта

```
src/themed_chat/
  app.py           сборка приложения: зависимости, middleware, маршруты
  settings.py      типизированная конфигурация (YAML + переменные окружения)
  api/             HTTP: ключ и сессии, лимиты, маршруты, формат ошибок
  chat/            сценарий чата без привязки к HTTP и БД: сервис, порты, guard.py (защита темы)
  adapters/        PostgreSQL (SQLAlchemy, Alembic) и клиент LLM на httpx
  migrations/      схема БД
  web/             HTML, CSS и JavaScript без фреймворков
```

Почему так.

- **FastAPI.** Типизированные запросы, валидация, асинхронность: ожидание модели не блокирует остальных.
- **PostgreSQL.** История переживает перезапуск, пара реплик записывается атомарно. Миграции Alembic идут при старте под advisory-блокировкой.
- **Порты и адаптеры.** [chat/](src/themed_chat/chat/) знает только интерфейсы хранилища и модели. Тесты подставляют заглушки, а БД и провайдера можно менять, не трогая сценарий.
- **Вопрос и ответ одной записью.** Модель вызывается вне транзакции, готовая пара сохраняется разом. Если модель не ответила, вопрос сохраняется как `failed` и после перезагрузки виден с пометкой «Ответ не получен».
- **Cookie вместо токена.** `HttpOnly`-cookie недоступна скрипту, и XSS не украдёт сессию; токен в `localStorage` читается любым скриптом. Цена — CSRF, закрытый проверкой `Origin`.
- **Один клиент для любого API.** Небольшой клиент на `httpx` для `/chat/completions`: заголовки заданы явно, `OPENAI_*` и прокси из окружения не подмешиваются, редиректы не выполняются.
- **Без фронтенд-фреймворка.** Один экран; Markdown рендерится через DOM без `innerHTML`, страница работает под строгим CSP `default-src 'self'`.
- **Один процесс.** Лимиты в памяти, одна реплика: достаточно при небольшой нагрузке.

## API

Ошибки: `{"error": {"code": "..."}}`. `POST` и `DELETE` требуют `Origin`.

| Запрос | Результат |
|---|---|
| `POST /api/session` с `X-Access-Key` | `204`, cookie `chat_session` и `chat_guest` |
| `DELETE /api/session` | `204`, сессия отозвана |
| `GET /api/messages?limit=50&before=<id>` или `?after_revision=<n>` | История, `has_more`, `revision` |
| `POST /api/messages` `{"text": "..."}` | `201`, пара реплик; текст до 500 символов |
| `GET /healthz`, `GET /readyz` | Процесс жив; сервис готов и БД отвечает |

Параметры и коды ошибок: [docs/details.md](docs/details.md#api-подробности).

## Проверки

`make check` (Ruff, mypy, unit- и интеграционные тесты; нужен тестовый PostgreSQL в `TEST_POSTGRES_URL`) и `make e2e` (браузер). Ключ модели не нужен, в тестах стоит заглушка. Необязательные атаки на настоящую модель: `tests/llm_eval`. Команды: [docs/details.md](docs/details.md#тесты).

Helm-чарт [deploy/helm/themed-chat](deploy/helm/themed-chat/Chart.yaml): одна реплика, внешние Secret и PostgreSQL. Инструкция: [docs/deploy.md](docs/deploy.md).

## Что можно доработать

- Повтор неотвеченного вопроса одной кнопкой: сейчас он возвращается в поле ввода.
- Серверная идемпотентность отправки: после потери ответа клиент сверяется с историей и сам решает, повторять ли запрос.
- Лимиты в общем хранилище (Redis) и несколько реплик.
- Личные учётные записи вместо общего ключа: своя история и отзыв доступа для одного человека.
- Потоковый ответ и контекст диалога: сейчас модель видит только текущий вопрос.
- Защита темы целиком на LLM-классификаторе: добавить детерминированные проверки и регулярный прогон `tests/llm_eval`.
- Резервное копирование БД, метрики и мониторинг квот провайдера.
