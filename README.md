# Кофейный бариста

Одностраничный помощник по домашнему завариванию кофе. История одна для всех участников с ключом; не отправляйте личные данные. Gemini получает системную инструкцию и текущий вопрос, но не всю историю.

## Быстрый запуск

Нужны Docker с Compose v2 и [ключ Gemini API](https://aistudio.google.com/app/apikey). Выполните из корня клонированного проекта:

```sh
cp .env.example .env
${EDITOR:-vi} .env
docker compose up --build -d --wait
```

Заполните `APP_ACCESS_KEY` (8–255 символов: `A–Z`, `a–z`, цифры, `-`, `_`), `APP_SESSION_SECRET` (случайный, не короче 32 символов и не равен ключу доступа) и `GEMINI_API_KEY`. Например, сгенерируйте два независимых значения командой `openssl rand -hex 32`, выполняя её отдельно для каждого секрета. В браузер вводится **только `APP_ACCESS_KEY`**.

Откройте **http://127.0.0.1:8000**. Не используйте `localhost` вместо `127.0.0.1`: API сверяет точный origin. Если порт занят, запустите, например, `CHAT_PORT=8080 docker compose up --build -d --wait` и откройте `http://127.0.0.1:8080`. При явно заданном `APP_AUTH__PUBLIC_ORIGIN` укажите тот же адрес и порт. `docker compose down` останавливает приложение, не удаляя историю; `down -v` удалит именованный том и данные.

**Без Docker**, при наличии [uv](https://docs.astral.sh/uv/) и заполненного `.env`:

```sh
uv sync --locked
uv run --locked uvicorn themed_chat.app:create_app --factory --host 127.0.0.1 --port 8000 --ws none
```

## Конфигурация

| Где | Что задаётся |
|---|---|
| [config/app.yaml](config/app.yaml) | Заголовок, поставщик, модель, системный промпт, таймаут, лимит ответа, тип хранилища и время жизни сессии. После изменения нужен перезапуск; в Compose YAML входит в образ — пересоберите его. |
| [.env.example](.env.example) → локальный `.env` | Три обязательных секрета из инструкции, плюс `DATABASE_URL` для PostgreSQL. Не включайте значения в Git или Dockerfile. Переменные процесса имеют приоритет над `.env`. |
| Окружение процесса | Незасекреченные настройки можно переопределить именами вида `APP_СЕКЦИЯ__ПОЛЕ`, например `APP_LLM__MODEL` или `APP_AUTH__PUBLIC_ORIGIN`. В локальном запуске `uvicorn` обычные ключи из `.env` не читаются: экспортируйте их или меняйте YAML. Compose передаёт `.env` в окружение контейнера. |

SQLite — по умолчанию: файл `data/chat.sqlite3` вне Docker, каталог `/data` на постоянном томе в Compose. Для PostgreSQL укажите `db.backend: postgresql` или `APP_DB__BACKEND=postgresql` в окружении, затем задайте секретный `DATABASE_URL=postgresql+asyncpg://user:password@host:5432/database`. База должна существовать и быть доступна приложению; контейнеру нельзя указывать `127.0.0.1` для БД на хосте. Допустимый URL-параметр — `ssl`, например `?ssl=verify-full`. Alembic применяет схему при запуске; смена БД не переносит историю. Автоматический запуск миграций рассчитан на один процесс приложения.

Если модель недоступна для вашего ключа, замените `llm.model` на доступную в [каталоге Gemini](https://aistudio.google.com/docs/models). Сервис не подставляет фальшивый ответ при ошибке провайдера.

## Устройство проекта

- [app.py](src/themed_chat/app.py) собирает зависимости и управляет жизненным циклом SQLAlchemy и асинхронного SDK. `create_app()` позволяет подставить текстовый генератор и согласованную пару репозиториев.
- [api/](src/themed_chat/api/) отвечает за маршруты, проверку ключа и сессии. Браузер отправляет `X-Access-Key` только при входе и затем использует подписанную HttpOnly cookie. Сессия даёт гостевой ID, а не учётную запись; клиент не выбирает автора запроса.
- [chat/](src/themed_chat/chat/) содержит сценарий и порты. Вызов модели выполняется **вне** транзакции; только готовая пара реплик сохраняется вместе.
- [adapters/](src/themed_chat/adapters/) реализует доступ к БД и Gemini; [migrations/](src/themed_chat/migrations/) содержит версии схемы. [web/](src/themed_chat/web/) — HTML, CSS и JavaScript без фреймворка.

| Запрос | Результат |
|---|---|
| `POST /api/session` | Проверяет `X-Access-Key` и выдаёт cookie (`204`). |
| `GET /api/session` | Проверяет, что сессия действует (`204`). |
| `GET /api/messages` | Заголовок и общая история; дата и время в UTC. |
| `POST /api/messages` с `{"text":"Как заварить фильтр?"}` | Сохраняет и возвращает пару реплик (`201`). Предел — 500 Unicode-символов, пробельные сообщения не принимаются. |

Закрытые маршруты требуют сессию. Для запросов, меняющих состояние, сервер требует точный `Origin`. После истечения cookie повторный вход создаёт нового гостя; история остаётся общей.

## Проверки

```sh
make check
uv run --locked --group browser playwright install chromium
make e2e
```

`make check` проверяет lock-файл, Ruff, типы mypy, документацию, unit- и HTTP/API-тесты. Для прогона общего интеграционного контракта ещё и на PostgreSQL задайте `TEST_POSTGRES_URL` до запуска `make check`: используйте отдельный тестовый сервер и роль с правом `CREATEDB`. Тест создаёт и удаляет только свою временную БД. Браузерный тест использует Chromium и запускает реальный HTTP-сервер с временной SQLite. Тестовый набор не требует ключа Gemini; адаптер отдельно проверяется с реальным SDK и локальной подменой HTTP-транспорта.

## Что можно доработать

- Пагинация истории, лимиты входа и генерации для публичного деплоя, мониторинг квот.
- Серверная идемпотентность запроса. Сейчас при потере ответа интерфейс просит проверить историю, прежде чем разрешить повтор; это не гарантия однократной записи.
- Отдельный запуск миграций для нескольких реплик, резервное копирование и перенос данных между БД. Вместо общего ключа — индивидуальные учётные записи, если требуется личная история.
